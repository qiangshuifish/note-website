# 结束语 | 不要温和地走入那良夜

你好，我是 Tyler。

不知不觉这门课已经步入尾声。感谢你一直以来的支持和陪伴。

借着结束语的机会，比起再回顾一遍前面的内容，我更想和你聊一件事：当 AI 越来越强，也越来越深入真实世界时，工程师究竟站在什么位置？这个问题，可能比我们学会了多少种工具更加重要。

## 人类究竟怎样与 AI 对话？

乍一看，人类已经找到了一种与 AI 对话的方法。

你在聊天框里写下一段话，模型读懂它，再用自然语言给出回答。这样的交互足够自然，以至于我们很容易把全部注意力都放在 Prompt 上，仿佛人与 AI 的对话，只发生在一问一答之间。

但学完这门课，你已经知道，真实情况远没有这么简单。模型并不能直接看见人的意图，也不能直接理解它所在的世界。每一次推理开始以前，Harness 都要重新组装 Context，把当前任务、历史对话、项目规则、相关记忆和环境状态放到模型眼前。模型想要改变现实，也不能只靠生成一句话。它要通过 Tools 提出动作，经过 Permission 与 Policy 的检查，再由 Harness真正执行。

任务结束以后，模型说“做完了”还不算数。Verifier 要用产物、测试和环境变化重新验证结果。一次经历是否值得留下，也要经过筛选、反思和版本管理，才可能进入 Memory，或者成为下一次可以调用的 Skill。

因此，人类与 AI 的对话，从来不只是一段 Prompt。

我们把人的意图、知识和偏好组织成 Context，把人愿意交出的能力接成 Tools，把不能逾越的边界写进 Policy，再用 Verifier 告诉系统，什么才是人真正认可的结果。人过去的经验，则通过 Memory 和 Skill，继续影响 AI 未来的判断。

这些部分合在一起，才组成了人类与 AI 对话的完整语言。而工程师，正是这套语言的设计者。

## 工程师站在对话的两端

工程师首先要把人类的世界翻译给 AI。

人的要求往往含有大量没有说出口的背景。哪些资料可信，哪些动作危险，什么事情可以自动完成，什么事情必须停下来征求同意，什么样的结果才算真正完成。这些判断不会因为模型更聪明，就自动出现在系统里。工程师必须把它们变成上下文、接口、权限、状态和验收条件，让人的意图在机器世界中拥有可以执行的位置。

与此同时，工程师也要把 AI 的世界翻译回来。

模型为什么在这一轮看见这些信息？一项工具为什么会在此刻出现？哪条权限允许它改变环境？一段经历又为什么被写进长期记忆？这些过程如果不能被还原成轨迹、证据和可以理解的系统变化，人类最终看到的就只剩下一个结果，却不知道这个结果从何而来。

所以，工程师不是单纯替 AI 实现功能的人。我们站在这场对话的两端，把人的目标、价值、边界和责任带进系统，也把 AI 的判断、行动与影响重新带回人类可以理解的世界。

从这个意义上说，工程师正代表人类与 AI 对话。

这不是一句宏大的口号，而是一项每天都会发生的具体工作。我们选择什么进入 Context，决定 AI 此刻能看见怎样的世界；我们开放什么 Tools，决定它可以怎样改变世界；我们设计怎样的 Verifier，决定系统会把什么当作正确；我们允许什么经验进入 Memory 和 Skill，则在悄悄决定这个 Agent 将来会成为什么样子。

每一项看似普通的工程选择，其实都在替人类回答同一个问题：我们希望怎样与这个新的智能相处？

## 当 AI 从回答者变成行动者

大模型只回答问题时，一次错误最多生成一段让人不够满意的文字。Harness 拿到文件、消息、终端和业务系统的写入权限以后，同样一次错误判断却会真正改变环境。

用得越久，你还会把更多事情交给它。最初，你只让它查找资料。后来，你开始让它修改文件、发送消息、推进任务。再往后，你希望它在自己离开屏幕以后继续工作，记住过去的约定，并从成功和失败中形成新的 Skill。

人的指令正在变少，系统拥有的时间、记忆和权限却越来越多。人与 AI 的对话，也从一次回答，变成了一段可以跨越时间、持续改变现实的关系。

这时，工程师的工作不但没有变少，反而变得更加重要。我们不再需要守在每一次工具调用旁边，却要决定哪些信息可以进入工作记忆，哪些动作必须等待批准，什么结果才算真正完成，什么经历值得留下，以及一项新能力需要多少证据才能发布。人的位置，从循环内部最忙碌的操作员，逐渐移到了系统边界的设计者。

人的注意力可以退出执行循环，人的理解却不能退出整个系统。

如果一项记忆被召回，我们应该知道它为什么在此刻出现。如果一项动作被允许，我们应该知道它经过了什么边界。如果 Agent 修改了自己的 Skill，我们也应该知道它依据什么经验，经过什么验证，又能否在出错以后撤回。

否则，即使事故还没有发生，我们也已经开始失去对系统的控制。因为 AI 的能力在增长，人对这套能力的理解却在退化。原本的对话，最终会变成一方不断行动，另一方只能接受结果。

## “与你共同成长”有两个主语

Hermes 为自己写了一句很好的介绍：The Agent That Grows With You，与你共同成长的Agent。

这句话里最重要的，其实是“与你”。Agent 要成长，人也要成长。

Agent 的成长，不是聊天记录越来越长，也不是 Skill 目录不断变大，而是经过验证的经验真正改变了下一次行为。人的成长，也不是记住更多产品名称和命令，而是逐渐形成一套系统判断，能够理解一次行为为什么发生，发现问题来自模型还是 Harness，并在必要的时候重新拿回控制。

如果 Agent 的能力越来越强，工程师却越来越不知道它为什么这样行动，这不叫共同成长，只是依赖越来越深。

我们当然不必为了证明自己仍有价值，重新盯住每一次模型调用，也不必把已经交给系统的工作全部拿回来。工程师真正需要保留的，是持续学习的能力，以及理解、质疑和修正这套系统的能力。

每开放一项权限，每接入一种记忆，每增加一个自动循环，每允许系统生成一项新的 Skill，都意味着人与 AI 的关系又向前走了一步。Agent 在学习怎样替我们完成更多工作，工程师也要学习怎样让这份能力始终清楚、可靠，并且服从人的目标。

只有两边都在成长，这场对话才不会逐渐变成服从。

## 工程师要把什么带进未来？

说到这里，我总会想起《星际穿越》里的库珀。

我一直觉得，库珀是一名工程师这件事很重要。进入一个人类从未抵达的世界时，他带去的不只是一艘飞船，还有人类面对未知时最宝贵的几种品质：好奇，理性，对证据的信任，以及在没有现成答案时仍愿意作出判断并承担结果的勇气。

今天，工程师也站在另一片未知世界的入口。

我们是最接近 AI 真实运行过程的一群人，也最早看见它的能力与边界。当其他人只看到结果变得越来越好用时，我们还有机会拆开系统，看见指令怎样流转，Context 怎样组装，权限怎样放行，错误又怎样被放大。

这种接近，不只是一种职业优势，也意味着一份不能轻易交出去的责任。

AI 的声音越响亮，人类在这场对话中的声音越不能变得模糊。工程师能为这场技术变化留下的，不应该只有更多自动化和更高效率，还应该让越来越强的技术始终可以理解、可以验证、可以约束，并且始终有人愿意为它造成的结果负责。

如果说工程师是这个时代需要保留的一束人类之光，那么这束光，就是人类在面对一个更强大的智能时，仍然能够理解它、回应它，也始终没有忘记自己是谁。

## 不要温和地走入那良夜

现在，这篇结束语的题目也有了更具体的含义。

这里的“良夜”，不只是你合上电脑以后，Agent 独自工作的那个夜晚。更值得警惕的，是另一种看起来十分舒服的黑夜。Harness 越来越能干，你便把越来越多的工作交给它。它会记忆，会调用工具，会总结经验，甚至会修改自己的 Skill。与此同时，你也慢慢不再追问，这些能力究竟是怎样发生的。

不要温和地走入那良夜，不是要我们拒绝 AI，也不是要把已经交给系统的工作重新拿回手中。它只是提醒我们，不要在自动化面前，提前让自己的好奇心、理解力和判断力退休。

你可以把执行交出去，不能把判断能力一起交出去。可以让注意力退出每一步，不能让认知退出整个系统。不要让 Harness 学会越来越多，而你自己停止学习。

我们可以把重复劳动交给机器，把理解世界的好奇心和判断力留给自己。这样，当屏幕真正暗下来时，我们交出去的是执行，不是方向。得到的是自由，而不是失控。

感谢你陪我走完这段旅程。只有真正的热爱，才能让漫长的学习过程变得有趣而充实。希望在这个浮躁的时代里，我们都能在技术带来的宁静与快乐中不断成长。

最后希望你抽几分钟时间填一下后面的结课问卷，我会认真参考大家的反馈。
