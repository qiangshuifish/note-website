直播回放 | 从独立作业到经验成长：企业AgentHarness落地指南 ​

  • 今天讨论三个关键词：独立作业、经验成长和企业落地。它们分别对应长程 Agent、递归自进化，以及把 Harness 嵌入真实业务流程。直播嘉宾 Tyler 国内头部大模型团队算法负责人

你好，我是 Tyler。

从今天直播的标题里可以看到三个关键词：独立作业、经验成长、企业落地。

独立作业背后是什么？就是长程智能体，也就是 Agent。经验成长对应的就是 RSI（递归自进化）。企业落地呢，就是企业落地的 Agent Harness——它和我们平时用的 Code Agent 不完全一样，把 Harness 发挥到了极致。

最近 OpenAI 放出了 Codex API 的服务，这个服务背后代表的是什么？其实是产业界已经做了很久的一些事情，OpenAI 把它标准化了，给大家放出来了。

老板让我落地 Agent，到底该学什么 ​

很多朋友有这样一个疑问：我在企业里面，老板经常让我落地 Agent，那我到底应该学什么呢？

现在大家面对的场景大概就是这样的：某一天在工位坐着没什么事，老板突然走过来说，哎，最近 AI 太火了，都在搞 AI，咱们不搞不行了，不能老用传统做法了。你调研看看，下周给大家讲一讲，咱们有没有什么能和 AI 结合的地方。

这时候你就会非常 confuse，指着自己说，啊？我？内心想法可能是：你又不给我资源，又不说往什么方向做，我哪知道该做什么。这都是大家非常困惑的。

所以今天也把大家的问题分成了两大类：一大类是说我们要往业务里落，哪些技术是真正有价值的；还有一大类是说技术太多了，我该怎么学，到底挑哪些去学、怎么筛选。像 Harness框架就这么多，什么 Claude Code、OpenCode、Codex、OpenHands，这么多，我到底学哪个？

为了回答这些问题，我们首先要看一下技术发展过程中呈现的规律，再去筛选哪些重要、哪些不重要。今天分成四个部分，这四个部分就是为了讲清楚前面的问题。

第一部分，我先帮大家梳理一下这一轮的发展脉络。这一轮 AI 浪潮，已经进行了四五年了，只不过它发展得太快，这个过程当中发生了什么，这么多事情是不是都值得学，时间有限的话到底学哪些。

第二部分讲企业落地，大家现在使用 Harness 的时候和企业用 Harness，其实是完全两套逻辑，今天给大家讲清楚为什么。

第三部分跟 RSI 相关，RSI 听起来很 fancy、很高级，它和我有什么关系？其实关系很大。

第四部分是大家非常关心的话题，为什么学、学什么、怎么证明我会了。

从 Codex 出发：这一轮 AI 浪潮的关键节点 ​

我们先回顾一下这一轮 AI 浪潮都发生了什么。

  • 这个地方有一个非常有趣的事情。看过《星际穿越》的同学应该很了解这张图，这张图发生在库珀去宇宙之前。他的女儿说，不知道怎么了，咱们家书柜后面好像闹鬼一样，天天有人往下面推书。后来他发现推下来的书是摩斯码信号，写的是什么呢？写的是 Stay。他不知道这个 Stay 留下来是什么意思。直到有一天，他爸说我要去拯救全人类了，为了让子孙后代、尤其是你，这个地球上的人可以存活下来，我觉得我有责任要去。去呢，是为了拿回来一个答案。这时候他女儿就说，书柜后面的 Ghost 告诉我们说你要留下来。这个故事讲的是什么呢？答案在一开始就已经出现了。因为后面推书柜的那个人，就是未来的他的父亲。他在书柜后面已经知道答案了，只要在这等几天，再推一推，答案就发回来了。但他的父亲还是去了。这个故事有更深一层的意义，和现在非常 match：如果他的父亲真的 Stay 下来了，那书柜后面是不是就没人推了？他是不是就收不到这个信号了？

这个故事和我们今天的关系是什么呢？OpenAI 一开始推出的第一个商业化产品就是 Codex，其实不是 ChatGPT。很多人的记忆是很模糊的，总觉得 GPT 出现之后第一个商业化产品是ChatGPT，其实不是，是 Codex。大家说兜兜转转四五年回来了，发现还是 Codex。大家就会马后炮，或者批评说，当时 OpenAI 为什么不从第一天开始就做 Code Agent，这个事情能早好几年就过来。我举这个例子就是告诉大家，这个批评是不成立的——你飞不到那个地方，就传不回来这个信号。中间不做这么多摸索，就得不出这个结论。

非常有趣的是，这个答案确实在一开始我们就看到了。从 2021 年 8 月，OpenAI 就推出了Codex，作为它的第一个商业化产品。当然有人说它更早的商业化产品是把模型做成 API 向外输出模型能力。如果这么算的话，第二个商业化产品就是 Codex，但它绝不是 ChatGPT。所以我们一开始就发现了大语言模型的 killer app 就是编码这件事，只不过中间兜兜转转发生了很多事。

在 Codex 之后，行业向各个方向去探索，不知道哪个方向能把我们带向 AGI，而且其中有很多方向是非常赚钱的。比如说陪伴类的需求，Character.AI，相信有些关注的同学很早就知道这家公司了。还有最近非常火的 AI 短剧，不用说了，大家所有人都看过了，而且越来越逼真，营收也非常高。XR 等技术也在发展。

而如果我们回归现实，关注企业内的 Agent 落地，或者想去做一个有深度的 AI 技术，我建议大家还是吃“红丸”，走出虚拟世界，扩大 Agent 在现实中的能力。

选了红丸之后，走向的必然就是慢慢通向 AGI，去扩展人的能力边界，然后慢慢人变成一个星际物种。大家看 TARS，其实也是《星际穿越》当中的 AI，它可以驾驶飞船，人在上面冬眠，人去做星际航行。当然如果 RSI 让我们快速逼近 AGI 的话，可能我们这一代人就可以看到类似的图景了。

回到这里，从 Codex 开始，如果用刚刚说的吃红丸路线去筛选，这一路发生的关键的、值得学习的节点就这么几个。从最早的 Codex，到之后的 SWE-Agent，再到后面的 Devin，当然Devin 有一些争议，但我们认为它的符号意义非常重要。再到后面的 Cursor，应该是四五个藤校的创始人，花了三四年时间把公司卖了 600 亿美金。再到 Claude Opus 成功地从 0 写了一个 C 的 Compiler，这个 Compiler 可以直接把 Linux Kernel 编译通过，这就是一个质变的点了，没有人再会去 challenge 说 AI 写代码有什么事情完成不了。因为你要知道很多大厂都没有这个信心敢去开发一个 Compiler，都不一定有信心能凑出这么一个团队的人来开发一个Compiler。

一个一个说。首先是 SWE-Agent，这个工作背后也有一个最近非常有名的人，就是姚顺雨。当时他们用 React Agent 加上 ACI（Agent Computer Interface）把软件工程当中的一个任务抽象成了一个 GitHub issue 和最后的提交 PR，很好地抽象了这个任务，让大家第一次看见智能体是可以在真实项目当中完成任务的，尤其是完成编码任务。

之后就是 Devin。Devin 更多体现的是它在数字员工上的概念，它把 Terminal、Browser、我们用的 IDE 全都 combine 在了一起，说它是一个数字的 Engineer。其实在这个时间点之后，行业内也涌入了很多血液和力量，它起到的符号意义很重要。虽然后期大家对它争议很大，但它还是起到了正面的推动作用，尤其是后来还有 OpenDevin，我们知道那其实是 OpenHands的前身，都是这么一步一步来的。第一次以数字员工的形式出现。

那之后呢，Cursor。Cursor 经常会发布一些研究，比方说它用诸多智能体干了一个什么事情，发现了一个什么特点，我也建议大家都去看看他们的报告。这个地方其实就是它用Cursor 做出了一个 Browser，可以直接渲染页面了。大家要知道，除了 Compiler 刚刚说的之外，Browser 也是非常难写的。市面上你知道的 Browser 基本上就是那几家有实力的在做。

更进一步，就是大家都知道的 Opus，直接把 Linux Kernel 编译通过了。当然不是 Opus 编译通过了，是 Opus 写出了一个 Compiler，把它编译通过了。这个象征意义简直太大了，整个行业内不会有人说谁的编程能力还能比它强，Jeff Dean 也不行。也不会有人说有什么单个任务它无法完成。当然大家说它在企业的 brownfield 上会有横冲直撞的问题，这个我们也是有办法解决的。我们先回到它能力本身来讲，在这个时间点，大家已经很少有人会去 challenge 它的能力了。

RSI 是什么：递归自进化的三条路线 ​

在这个质变的时间点之后，我们再来看 Code Agent 本身还有哪些特点。还有一个非常有趣的现象出现了：Code Agent 是一个编码工具，它可以用来研发下一代的 AI 研发工具和系统。这些 AI 研发工具和系统呢，又会去研发下一代的 AI 研发工具和系统，这就是我们所说的递归自进化当中的递归。它不断地转起来，一旦转起来之后，放大效应是非常大的。它有点像电路上的短路，短路时间久了，电流无限大，带来的能量非常惊人。

所以我们说 RSI 这个递归的自举过程，一定程度上可以比喻成什么呢？比喻成我们通往 AGI过程当中的一个虫洞，它可以帮我们把时空折叠了。因为 RSI 放在那，它自己转起来的话，可以快速减少我们通向 AGI 的时间，是非常有价值的。当然达到这种程度的 RSI 还有很多路要走，但现在大家已经看到了它的意义和价值。一旦我们定义好这个问题之后，解决它的速度就会越来越快。

这个地方也有一个比喻。我们回到上一张图，其实这个流程和学 CS 背景的同学在学校学的编译原理当中的逻辑是非常一致的。早期第一个 C 语言的编译器，它其实不是用 C 语言写的，不然就会出现鸡生蛋、蛋生鸡的问题。第一个 C 语言的编译器是哪来的？是用汇编写的。直到有一天，一个质变的点，汇编写的 C 的 Compiler 已经有足够的 feature 可以去开发下一代的 C 的 Compiler 了，这个时候我们就叫它自举了。在那个时间之后，Compiler 的发展速度就出现了质变，质和量都出现了质变。现在 RSI 的意义比那个还要大，所以现在 RSI 这个问题非常重要，大家都在思考怎么在自己的企业当中用起来。

那 RSI 是什么呢？就是一代 Agent 的能力用来开发了下一代的 Agent，下一代的 Agent 能力又用来开发了更下一代的 Agent。

  • 当然这里还有一个定义的问题。如果我们较为宽松地讲，下一代的开发用到了上一代增进的技能，这个都叫 RSI，无论是模型上的、数据上的还是框架上的，都算。当然还有一些更严谨的 RSI 定义：我所开发出来的下一代技术，如果它不能更好地服务于我开发更下一代的技术，满足不了这个严格目标——这种隔代传递的严格目标——我们不称它为 RSI。因为我们希望它是有传递性的。只不过现在大家聊 RSI 聊得非常泛，甚至管 Reflection 也叫RSI，说我反思了，下一次做得更好了，这个也叫 RSI，当然也是说得过去的。所以大家要理解，最严格的 RSI 和相对泛化的 RSI，中间这个光谱是存在的。

那大家在学习的过程当中，就会发现有几个拐点。

首先是任务的脚手架，比方说 LangChain 这类的。23 年的时候我就跟大家说，LangChain 不要花太多精力去学，把一个简单的问题复杂化，真的很占大家的精力。当时我也跟大家说要去学什么呢？要去学类似 Harness 这类东西，上下文工程的这些事情，只不过当时还不叫上下文工程，当时跟大家说的是企业级的 AI 系统，但其实那个架构就是上下文工程的架构。更进一步，就到了现在大家所用的这些通用行业，我们进入了长程智能体的时代。再下一步，就是我们说的自进化。

一般来说，通用 Harness 和我们现在使用的以 Codex 为代表的，那自进化的 Agent 呢？尤其是以 Memory 和 Skill 这种通过数据自进化的，大家聊得比较多。当然这都是大家抓得到实体的东西，更前沿的东西学起来就会更分散一点。

所以我们说 RSI 其实有三条路线。如果要覆盖 RSI 概念的全部的话：

第一是数据的路线，比方说我的 Memory、我的 Skill，一般来说它还是在 Agent 认知框架的概念当中的，事实性记忆、程序型记忆、情境类的记忆不断进化。

第二是框架类的，比方说我这一代的 Harness 用来开发下一代 Harness。

第三是模型训练，我这个 Harness 在工作过程当中所产生的 Rollout——什么叫 Rollout 呢？就是 Harness 解决一个问题从开始到结束的整个 trace，叫 Rollout——用来训练了模型，模型的能力增长了，这个模型又装入了 Harness，去生成更高质量的 Rollout，不断地转起来。当然这个过程当中，Harness 也可以参与到模型的开发。一旦连 Researcher 或者算法工程师都退出了模型开发的链路，那这个速度就更惊人了。

主要是这么三条路线。第一条路线，相信大家都有使用经验。比方说你在使用 Harness 框架的过程当中，让 Skill 去完成一个功能，完成的过程当中你发现哪个地方做得不太好，你希望它下一次少走一些弯路，你就会跟它说，刚才这些地方是不是有些地方下一次能优化一点？你能不能把它固化到你的 Skill 里面？它说，确实哈，这几个地方我觉得可以优化一下，Skill 更新一下，下次做得更好。这个对大家来说都是非常好理解的数据路线。我觉得大家在上车 RSI这件事情的时候，也建议大家选数据这个路线，一点一点地再往中间去切。

那框架路线说的是什么呢？就是我用新一代 Harness 去开发更下一代的 Harness。这个地方大家经常会出现一个问题：比方说你们内部开发了一个 Harness 框架，from scratch 去开发，但是你这个开发过程当中用的是 Claude Code，你用 Claude Code 不断地迭代你的 Harness框架，或者你用 Codex 不断地迭代你的 Harness 框架。你这个时候就最好不要出来公开说你在做 RSI，这个就有点说不过去了。直到有一天，你的水平和 Claude Code 差不多了，你开始用你的框架开发你的框架了，这个时候你可以出来说，那我们 RSI 了开始。这个是说得过去的。我相信举这个例子大家立刻就能理解框架路线在做什么事情。

更下一步，这个其实就是 Anthropic 放出来的一个截图：通过 Claude Code 产生的 Rollout，收集回来、遥测收集回来去训练下一代的模型，下一代的模型进入 Claude Code 之后又产生更高质量的 Rollout，再进入下一代模型。甚至 Claude Code 还要参与到模型训练的整个Pipeline 的建设当中。如果让整个训练 Pipeline 的人慢慢可以退出的话，那这个就是我们说的能量最大的 RSI。但到这一天还有一段路要走，不过这个速度是在加速的。

企业落地：把经验接回真实工作 ​

讲到这，你对于 RSI 也有了基础认知，但它和我在企业落地具体做的工作有什么关系呢？

举一个例子。你在企业里做具体工作的时候，数据 RSI 其实是很好进入工作流程的。首先你有一个真实的任务，在处理过程当中留下了一个经验，你把它固化到 Memory 和 Skill 当中，采用了之后再回来，这其实就是一个 RSI 的 Loop，递归就在这个地方产生了。下一次工作用上了上一次有效的经验，这其实就是一个很小的 RSI Loop 在企业当中的体现。

当然更进一步，如果严谨地去做的话，RSI 和传统 AI 系统当中的诸多要求就完全一致了。之前我给大家讲过很多 AI 系统建设的原则，其中就讲到了在线和离线的分层架构。

在线执行的时候，我要利用之前的一些 Experience、一些先验、生成的一些治理去帮助我们完成任务。离线的时候呢，我用这些模型所生成的在线经验去训练下一代的模型，加载上来。

这个 Loop 已经存在了几十年了。现在我们在做 RSI 的过程当中其实也是一样的，包括后面说的以 RSI 著称的 Harness 框架 Hermes，它用的也还是这个在线离线的 Loop。当然之前讲 AI系统的时候给大家讲得更细一点，有在线、近线、离线，只不过现在大家用 Harness 的时候大多都沉淀在了端侧让大家去用。所以基本上就是在线执行和后台学习，也就是在线和离线的概念。

比方说我们在企业当中落它的时候，各个研发团队经常落的第一个场景就是 On-call。为什么呢？背后的动力非常足。

  • 首先大家就很烦 On-call 这个事情，半夜被 Paging 起来之后一头雾水，又非常着急就要去解决问题，大家都希望这个工作不要由人来做。

  • 第二，几乎所有团队都有这类工作，只要你是一个 Engineer 团队，你都有这类工作。

  • 第三个特点是它整个处理流程非常标准化，大家可以把这个标准化的流程用 Agent 去做建模。

  • 第四个特点是工程师团队的文化——吃自己的狗粮，Agent 落地先给自己用，自己的狗粮吃着不错再给别人吃。一般来说大部分团队第一个落的场景基本上跟这个有关。

举个例子。一个告警来了，工程师拿着这个告警去找 Harness 去解决问题，这就是一个标准流程。只不过在这个流程当中，现在大家的做法是什么呢？我有一个 Harness 框架，本地的Codex、Claude Code、OpenCode，然后我拿 MCP 或者各类方法让它接到内部系统当中去排查问题，甚至有些系统打不通，我还要把日志什么的全都粘出来给它去排查。这其实根本达不到自动化 On-call、或者让它替我值班的效果，我还是要起床，或者起床之后还是一头雾水。

我们希望达到的状态是什么呢？Harness 作为一个数字员工，跑在企业内部，跑在它的平台上。前面我讲这个事情的时候，可能大家还是有点一头雾水，说什么叫 Harness 跑在企业呢？我们现在用这些 Harness 的时候，都是在我的电脑上一点一点去用它。

首先跟大家说一下，Harness 在发明的时候，至少在几个头部大厂发明的时候，主要目的不是为了和你一轮一轮交互去用。它的主要目的是什么？是嵌入到企业的运营流程当中。所以你看到，OpenCode 也好、Codex 也好，它们都是一个 Server 在跑，你可以 Headless 地用 API去调它。你发给它一个指令，只要提供给它足够的上下文，它长程地去跑，解决掉任务之后就应该在企业当中自动化地流转了，而不是人上去控制它。这个是大家一定要转变的思维。

所以我说在企业当中落它的时候，大家第一个想到的应该就是：它不是我电脑上起了一个类似办公软件的东西，我不断在跟它聊，不是的，而是一个服务在云上跑。

当然现在很多团队都在做一件事——原来我实现的一个服务，对时延要求没那么高，可以慢点跑，这种服务现在变成 Harness 加一个 Skill 都可以替代掉了，而且反而还增加了一些弹性、增加了一些趣味性和随机性。如果你说这个地方不需要弹性，就是让它 exactly 像之前那样执行，其实 Harness 加上各种功能也可以完成类似效果。

但如果你完全要求实时性，这可能不太行，可能要用一些新技术，比方说大家最近看到的 JEV模型，就能达到又要实时又要 exactly 一样的效果。

我们再回到经验成长这个主题。比如说我在使用 Harness 过程当中，或者业务流程当中、DevOps 系统当中、研发 Pipeline 当中嵌入了 Harness、嵌入了 Agent，我希望它越用越好，而不用我每一次都去改 Skill，行不行？因为随着业务上线，刚刚说的 Agent 加 Skill 其实就可以替代掉一些在线服务了。

如果用户的分布出现了变化、用户的需求出现了变化，我不希望每一次都要自己去调，我希望它能够跟着用户的需求自己去成长，这也是一种 RSI。能不能做呢？当然可以。那就用它历史上产生的 Rollout、轨迹的数据，让它自动地去 propose 一些新的 Skill，然后我们以一定的机制保证这个新的 Skill 是比原来的版本要好的，把它升级上去就 OK 了。

这其实就是 Hermes 提供的其中一个核心能力。所以为什么我说 RSI、为什么聊自进化的时候经常聊 Hermes？但是 Hermes 在做的过程当中也没有把 RSI 做得那么好，即便如此，它也是诸位可以抓到的相对来说实体的、比较完整的一个 RSI 实体了。它可以在后台自动地去复盘，把程序记忆、把认知架构当中各类的记忆全部更好地用起来。Hermes 本身就说它基于认知架构在做。认知架构我也说了很长时间，从斯坦福的人工智能小镇那个地方我就开始说这个事情了，其实就是 Agent 的一个架构的重新。

更进一步，怎么去生成更好的下一轮迭代的候选？这个其实离线能做的事情就非常多了。为什么要做在线和离线的分离呢？因为离线的优化可以给我们非常大的优化空间。这个地方我们生成多个候选，就类似于传统做离线模型训练的时候去做一些随机的梯度，甚至做多个模型版本的训练，让一些随机性引入进来，我们去选一个更好的候选，加快在线迭代的速度。因为离线是可以并行的，我们可以用猴子敲莎士比亚的方式，用无数个猴子并行敲，最后再去挑。当然这是有成本的，中间还是要做一个 Trade-off，但加几个候选我们还是加得起的，这是我们的优化手段。

这个路径和传统 AI 系统当中做模型训练的逻辑就差不多了。后面还要用在线收集到的真实数据、一些 Rollout 去比较离线当中的结果，离线验证的过程当中数据也需要进行科学的 Split 和科学的实验。

更进一步大家会说，如果我线上有诸多智能体跑在企业里面去完成各式各样的任务，或者诸多智能体在完成一组任务的时候，我们希望这些智能体生成的结果可以汇聚起来，然后去优化Skill、优化 Memory，这些 Memory 和 Skill 再扩散到各个 Agent 上去生效。这个就和传统 AI系统非常相像了，能不能做？当然可以，SkillClaw 就是做这个事情的。但是它最小范围能解决一个什么问题呢？大家很多人说，我在这个地方用了一个 Harness，在那个地方用了另一个Harness，我想让这几个 Harness 共用 Skill，或者他们在使用过程当中的经验可以共同让这个Skill 进化，可不可以？也可以用 SkillClaw，但就有点大材小用了。

最好的用法是让企业当中同一组任务起的多个 Harness 实例，它生成的 Rollout 共同地去更新这个 Skill，然后这个 Skill 在后面所有的实例当中去生效。这就是我们说的群体进化。比如SkillClaw，我如果在线所有的 On-call Agent 全都接得到它的话，那你每新起的一个 On-callAgent 就拥有了所有其他 On-call Agent 历史上的经验了。

在线执行的时候，你可以发现下面有共享的对象：有 Skill 的版本，还有之前的 Session，还有 Memory，还有 Profile。包括大家看 Codex 最近也在借鉴 Hermes，也不能说抄吧，它本身也是要做的，现在优先级提起来了——做历史 Session 的搜索，这其实 Hermes 一开始就带了一个功能，让它更好地复用历史经验。Hermes 本身的 Background Review 就有它的 RSI闭环，再加上 SkillClaw，它就可以做群体的演化。

最终可以形成这么一套 On-call Agent 和企业内部 Context 协同的方法、架构。这个我们说它才是一个企业级的 Agent 落地，而不是说你在电脑上学了很多 Claude Code 的 feature，我用来用去它就是一个很好的企业级落地了，不是。或者有些人在 CI/CD 当中集成了一个 ClaudeCode 去做 Code Review，那这个其实也是有点大材小用了。我们说它是要深度地 involve 到企业业务当中去做集成的，这才是真正发挥了 Harness 本身充分的价值。

学 AI 的目的是上车 ​

大家最终肯定还是会有这种功利的想法：那这个东西对我涨工资、对我求职有什么帮助？或者对我在 AI 行业的发展有什么帮助？我觉得这个问题大家问得非常好，而且我非常建议大家从这个角度思考问题。为什么呢？因为我一直觉得，大家学 AI 的目的不是为了增加一些饭后的谈资，也不是为了营造一些假象，觉得现在发展的这些东西我都搞懂了、都跟上了，其实我很安全，没什么事情。

我觉得都不是。大家现在学 AI 的目的应该就是快速地上车。什么叫快速上车呢？就用我现在所学的这些知识，在这个火车还在起步的阶段，拿到一张车票，赶紧跑到火车上面去，上这个牌桌。

因为一旦进入到这个行业之后，你会发现很多认知和大家想象的是不太一样的。行业的发展其实是特别快的，好在现在这个火车还在起步阶段，所以大家学的目的不是为了学而学，也不是为了谈资而学，也不是为了觉得我现在跟得上而学，应该是为了上车。上车之后你才能学得更快。

大家看到的这些面试题，其实和我们刚刚讲到的都有关系。什么任务使用 Agent？什么任务使用传统的专家系统和工作流？怎么理解 Harness？失败之后怎么恢复、怎么避免前面的重复执行？怎么保证幂等？哪些记忆适合加载、哪些适合检索？更新记忆的时候怎么找到最合适的？找不到怎么办？知识库要更新但线上要实时提供服务怎么办？

诸如此类，非常多，这里只是随便举了几个，现实比这个还要更复杂一点。

我觉得大家问出这个问题很好，大家学习有这么个目标也非常好。而且现在大家一定要上车，尽可能进入到和 AI 相关的行业。可能两三年前，上车还比较容易，那时候会点 RAG、会点NL2SQL，因为毕竟会的人还不多，关注的人不多，做 Agent、做 AI 的团队就说 OK 来吧，反正我们也在起步阶段，人也不好招。

但现在大家发现面试题一点点深了，再往后火车开起来之后，再上车就更麻烦了。所以如果大家下定决心要长期学一些技术、赶上这轮浪潮，重点是什么呢？学一些真正有价值的东西，拿到车票，快速上车。

学习的过程，我也希望大家不要“抽二手烟”，去听一些一线的人给你的信息，而不是满足于二手信息，那样反而容易带偏我们。
